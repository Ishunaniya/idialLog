# 1.12.2 复核工作台使用与核验

当前版本为 1.12.2，根目录发布程序为 `dialLog_v1.12.2.exe`；双架构构建分别位于 `build/x64/dialLog_v1.12.2.exe` 和 `build/x86/dialLog_v1.12.2.exe`。本文中的 `build/` 文件都是可重新生成的本地验证产物；删除不会影响已复制到其他目录的程序运行，历史截图和日志需要留档时请先移出。

## 入口和页面

左侧“工作台”分组新增“复核工作台”。内部主标签为“事件复核”“设备对比”“工作会话”；设备对比下再选择“设备归属”“前后对比”“多时期趋势”。此前的来源菜单快捷入口仍可打开设备归属。原有九个页面编号和 `Ctrl+1..9` 不变，命令行 `--tab=9` 打开新页。

小窗口使用整页纵向滚动，图表保留最小高度；键盘焦点进入下方控件时自动滚动到可见位置。统计正文、会话说明和证据详情可选择文字，支持复制。界面和导出使用当前中英文语言，人工备注、设备 ID、原始标签和日志证据保留原文；语言与字体设置独立于会话。

## 事件复核与证据链

事件看板使用完整载入来源，主界面的标签、消息、时间和指标快捷筛选不会隐藏这里的事件。可按设备或单来源、待复核/已确认/已处理、关键词和最短断网秒数筛选，并按发生时间或时长排序。来源归属的设备由用户指定；未指定的来源保留独立身份。同设备的多来源仍沿用日志来源和会话边界，不把同时发生的不同设备故障拼成一次事件。

选择事件后，四段证据链显示故障起点、实际恢复动作、联网恢复和业务成功。点击有证据的段，或在证据列表双击/按 Enter，可定位原始日志。详情同时显示原文件名、原行号和合并行号，支持复制全文和导出单文件 HTML。

联网恢复、流量增长和 ping 成功不自动升级为业务恢复。当前业务成功节点只接纳联网恢复之后、复核观察窗口内明确的 `BUSINESS_PROBE` 或 `APP_PROBE` 标签，且原文含 `result=ok`、`result=OK` 或 `result=success`。这只是已支持的证据形式，不意味着每种日志产品都会输出这些标签；缺少对应原文时明确显示“缺少明确证据”。失败探针不能算成功。

双击事件或按 Enter 打开原有完整事件复盘。备注通过复核窗口编辑；多选事件后可批量修改状态。保存失败会恢复原状态，不修改自动判定或原始日志。导出/复制的事件 CSV 包含设备、来源、时间、秒数、恢复状态及人工备注，文本字段处理电子表格公式前缀。

## A/B 交互对照

在“设备归属”填写设备 ID、固件和配置。非空相同 ID 表示人工确认同设备；空 ID 不自动归组。文件名、平台相同或时间相邻都不能代替设备身份确认。

在“前后对比”分别选择 A/B 来源或设备、完整起止日期后计算。可比较同来源的两个时期、同设备不同日志或不同设备。默认按各自起点对齐，也可切到真实日期轴；A 为蓝实线，B 为绿虚线。CSQ、RSRP、RSRQ、SNR、RSSI 都显示实际上报采样，RSSI 不从 CSQ 推算。SNR 的内部 0.1 dB 数值在图表、悬停和统计中换算为 dB。

悬停同时给出五指标 A/B、各自实际采样日期和 B−A。最多选取距光标时间 600 秒的最近点，超出时显示缺少采样。不能把不同时间的最近点解释为同步测量。

滚轮以光标位置缩放；Shift+滚轮或中键拖动平移；左键横向拖动框选。图内 `Ctrl+0` 或“恢复图表范围”恢复当前 A/B 全区间，`Esc` 取消拖动。“用 A/B 范围分析”将选中的原始时间范围与来源应用到主分析，并进入信号指标页，联动概览、指标、时间线、断网和结论。没有与该侧重叠的区间时提示，不切到无关时间。

统计保留有效采样数、均值、极值与 P10/P50/P90；分位数按采样秩计算，不按持续时间加权。缺失值显示缺失，恢复层级/动作只统计原文上报次数，不等于恢复成功次数。A/B 差值不证明固件、配置或其他变更造成差异。离线 HTML 保留缩放、框选、平移和五指标悬停；已导出的正文统计不会随网页框选重新计算。

## 多时期趋势

选择来源/设备、起止时间和步长：小时、天、7 天或自定义正整数秒。分段从用户指定起点开始，使用不重叠的闭区间，最多 3660 段。不是按当地日历周自动对齐。

每期提供实际记录数、观测时长、新发生断网、从之前跨入的断网、窗口内断网、累计断网时长、运行/全程可用率、五指标有效数和分布，以及日志上报的恢复标签、阶段、层级和动作次数。区间裁剪沿用现有统计规则；缺少区间外起止/启动证据时不能补成连续观测。

趋势图绘制每期有效采样的 P50。悬停显示完整时期、P50 和有效数 `n`，不会把期初坐标说成原始采样时间。无记录/无指标的时期保留为空，曲线断开，不补零、不推定为离线。HTML 也保留空时期、完整分布、恢复统计和交互提示，不引用外部脚本或资源。观察差异不作配置/固件因果判断。

## 完整工作会话

“工作会话”可命名、保存 ZIP 和重新打开，不要求有断网事件；空工作台也能打开已有会话。会话包括全部载入来源的原字节、设备归属/固件/配置、复核状态/备注、来源选择、主分析选区、标签/消息/起止条件、指标快捷筛选和显示列、A/B 选择及图表视窗、趋势参数、事件看板条件和书签。

包内新增 `session.json`，同时保留 `workspace.json`、`package-index.json` 和 `originals/*.log`。在会话入口只接受完整工作会话，不能把基础报告 ZIP 当作会话；也不将多个会话/其他日志混装成一个恢复状态。普通打开日志入口仍可打开受支持的原始日志和完整证据包。

重新打开时先校验 ZIP 路径、重复项、CRC、索引清单、SHA-256、来源身份和会话引用，成功后才替换当前文档；失败/取消保留原分析。原始路径已不存在也能使用包内原文重新解析。自动诊断按当前工具规则重新计算，人工记录与事实分开保存。

磁盘来源在导出时重新核对，修改或丢失的原文件不能静默搭配旧分析导出。BOM、CRLF 保留；压缩日志保存条目的未压缩原字节，不承诺保留原容器；粘贴内容保存剪贴板转换后的 UTF-8。最多 1000 个原来源、每个 256 MiB，全部未压缩内容及最终 ZIP 分别最多 512 MiB，生成文本每个最多 64 MiB；超限拒绝，不截断。

## 代码与配置

`workspace_tools` 是纯 C++ 模型，负责会话编码、独立来源事件、证据链和多时期分布；`workspace_state` 复用已构建指标计算各期统计，保留期外制式上下文。Win32 容器分离控件创建/路由与辅助操作，缓存图表排序/降采样和当前来源事件基础数据；悬停不重新解析所有日志。

根目录 `.clang-format` 基于 LLVM，采用 C++17、4 空格缩进、120 列、左花括号同行、指针星号靠类型，不重排 include。已使用 clang-format 23.1.1 批量重排 `src/`、`tests/`、`sim/` 中的手写 C/C++ 文件（包括 Win32 私有 `.inc`）及 `version.h`；排除第三方代码、生成的 `text_catalog.inc` 和 `text_ids.h`。共检查 108 个文件、重排 101 个，第二次检查无变化；变异测试的定位文本随排版更新，仍保留原来的故意错误行为。

## 1.12.2 源码排版与悬停重绘修订

本次保持版本 1.12.2，修订源码排版和悬停绘制，不改变诊断规则。

- `.clang-format` 明确函数定义间一个空行、连续空行最多一个、行尾注释前至少两个空格；工作台等密集实现按处理阶段分段。`make format` / `make format-check` 仅处理手写源码，排除第三方和生成词条。本轮检查覆盖 109 个文件；101 个无新增逻辑的文件与本轮排版前快照比较，非注释代码 token 一致。
- 变异定位允许代码空白变化，保留字符串和注释的原文匹配，要求整个源码集合中唯一命中。56 个变异仍全部被捕获，零存活、零片段失配、零验证异常。
- 导航悬停只使原条目和新条目失效，采用复用的绘图缓冲，移出和同条目内移动不再请求整栏刷新；按钮激活状态相同时不重复使按钮失效。输入框焦点装饰限定在边框区域。
- 工作台对比/趋势图缓存静态画面；普通悬停只恢复旧准线和绘制新准线。提示正文在时间或外观变化时更新，相同鼠标坐标不重复处理。信号指标页在原有曲线缓存之上缓存静态画面，仅更新提示框和准线所在区域；绘图区外没有活动悬停时不请求刷新。
- 图表缓存包含数据修订、时间范围、指标、尺寸、DPI、语言、字体修订和配色。字体句柄可能复用，因此字体重建另有修订号；窗口尺寸消息会使几何缓存失效，即使消息中的尺寸与原尺寸相同。缓存和绘图对象在关闭窗口/释放数据时清理。
